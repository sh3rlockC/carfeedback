# Flat Beige Workbench UI Redesign

## Summary

重做车型口碑系统前端视觉与主流程，把当前偏工程演示的界面改成高信息密度的业务工作台。新界面采用 Flat Design、米色主基调、左侧导航和顶部任务状态条，默认直接进入工作台总览。主路径切换为新任务中心体系，旧五步流程保留路由但从主导航隐藏。

## Goals

- 全站形成统一的 Flat Design 视觉系统，主色调以米色为底，配墨绿、炭黑和少量金色状态色。
- 让 2-4 个用户同时使用时，用户能快速理解当前运行任务、排队状态、车道占用和预计完成时间。
- 默认隐藏登录口令页，用户打开站点后直接进入工作台总览。
- 主流程切换为：工作台总览 -> 新建任务 -> 任务详情/进度 -> 结果仪表盘。
- 旧五步流程从主导航隐藏，但保留路由，避免已有链接失效。
- 引入 `lucide-react`，用图标提升导航、按钮、状态和表格操作的扫描效率。
- 文案改为业务化工作台语言，删除与长期语料库和增量采集冲突的旧说明。

## Non-Goals

- 不删除后端口令校验能力，只在前端默认流程中暂时隐藏。
- 不改变后端采集接口、任务数据结构或语料库模型。
- 不在本阶段删除旧五步页面。
- 不把移动端做成完整高密度工作台；手机只保证核心可用。
- 不重新设计外部采集器或任务调度策略。

## Visual System

### Direction

- 视觉风格：Flat Design。
- 主基调：米色页面底色和浅米色内容面板。
- 重点色：墨绿用于主按钮、活跃导航、关键正向状态。
- 辅助色：炭黑用于正文和高对比文本，金色用于等待、提示或需要关注的状态。
- 避免：玻璃拟态、霓虹科技感、复杂投影、过多渐变、大圆角卡片。

### Density

- 默认密度为中高密度，适合业务用户长期使用。
- 提供全站“紧凑模式”开关。
- 紧凑模式影响：表格行高、卡片间距、侧栏宽度、表单间距、字体层级。
- 密度状态应保存在本地浏览器状态中，刷新后保持。

### Layout

- 全站使用左侧固定导航 + 顶部当前任务状态条。
- 桌面宽屏显示完整侧栏和顶部状态指标。
- 平板折叠侧栏或压缩为图标导航，保留完整工作台能力。
- 手机简化为单列，保留查询、进度、结果查看和下载入口。

### Components

- 基础组件应包括：AppShell、SidebarNav、TopStatusBar、MetricTile、StatusBadge、FlatPanel、DataTable、DensityToggle、IconButton、PrimaryAction。
- 卡片和面板圆角控制在 8px 左右。
- 表格优先用于任务列表、队列、平台状态、结果矩阵等高密度信息。
- `lucide-react` 用于导航项、主按钮、状态标识、表格行操作和提示信息。

## Information Architecture

### Primary Navigation

主导航展示：

- 工作台总览
- 新建任务
- 任务中心
- 结果归档

兼容路由保留但不在主导航展示：

- `/passphrase`
- `/vehicle`
- `/candidates`
- `/progress`
- `/result`

### Entry Flow

- `/` 默认进入工作台总览。
- 口令页暂时隐藏，用户不需要先输入口令。
- 后端口令校验能力保留，便于未来重新启用。

## Page Design

### Workbench Overview

总览页是默认首页。首屏优先级为 B+A：

1. 运行中任务、排队状态、车道占用和预计等待时间。
2. 快速新建查询入口。

首屏模块：

- 顶部状态条：运行任务数、可用车道、今日新增评论、最近完成任务。
- 主区域：运行中任务和队列表格，展示车型、用户、模式、状态、预计完成时间、操作。
- 右侧或固定区域：快速新建查询，支持单车型和多车型对比，默认增量采集。
- 下方区域：最近完成结果、异常任务、语料库统计。

### New Task

- 新建任务作为主流程入口，而不是旧车型输入页。
- 支持单车型和 2-5 车型对比。
- 默认文案表达为增量采集。
- 表单应保持高密度，但要清楚区分车型输入、平台车系确认和采集选项。
- 不展示“全量重新采集”作为常规入口。

### Task Center

- 任务中心承载历史任务、筛选、状态查看和结果入口。
- 表格列建议包括：车型/对比组、任务类型、状态、进度、预计完成、创建时间、结果状态、操作。
- 支持紧凑模式。
- 筛选区不应占用过大首屏空间。

### Task Detail

任务详情页首屏按以下顺序组织：

1. 精确到分钟的预计完成时间。
2. 平台进度和车道状态。
3. 可操作选项。

必须展示：

- 预计完成时间，精确到分钟。
- 排队原因或当前瓶颈，例如车道等待、平台重试、报告生成中。
- 汽车之家和懂车帝各自的状态、进度、失败重试和车道占用。
- 操作按钮：继续等待、降级结果、取消任务、失败后重试。

### Result Dashboard

结果页采用综合仪表盘优先，不再只是大段报告。

首屏展示：

- 核心结论。
- 关键指标：累计评论、新增评论、平台完整度、报告状态。
- 维度矩阵摘要。
- 下载入口：Excel、报告、词云、打包结果。

向下展开：

- 详细一页纸报告。
- 关键词和词云。
- 评论样本。
- 时间报告和采集产物。
- 多车型对比矩阵。

结果页目标是让用户快速判断：结论是什么、文件在哪里、数据是否完整。

## Copy Guidelines

- 主名称使用“车型口碑工作台”。
- 优先使用业务用户能理解的词：运行中任务、预计完成、增量采集、历史语料库、结果归档。
- 弱化或移除“情报舱”“终端”“AGENT_ID”等演示或技术化表达。
- 删除或改写以下过时文案：
  - 三天后删除
  - 72 小时复用
  - 每次重新采集
  - 默认口令入口
- 按钮文案使用明确动作：新建查询、查看进度、下载结果、继续等待、生成降级结果。

## API And Data Assumptions

- 第一版 UI 优先复用现有 API。
- 如果缺少总览聚合接口，先用任务列表和进度接口拼出可用总览。
- 如果缺少准确车道占用接口，第一版可从任务状态、平台进度和 worker/agent 信息推导展示。
- 后续可以单独补后端聚合接口，不阻塞第一版 UI 重做。

## Implementation Boundaries

推荐实施顺序：

1. 引入设计 token、`lucide-react`、AppShell、左侧导航和顶部状态条。
2. 隐藏默认口令流程，让 `/` 进入工作台总览。
3. 建立密度模式和基础组件。
4. 重做工作台总览。
5. 重做新建任务页。
6. 重做任务中心和任务详情页。
7. 重做结果页。
8. 处理旧五步流程兼容视觉，确保路由仍可访问但不在主导航展示。

## Testing Plan

- 运行 `npm --prefix apps/web run typecheck`。
- 运行 `npm --prefix apps/web run build`。
- 使用浏览器验证桌面和平板宽度下的总览、新建任务、任务中心、任务详情、结果页。
- 验证 `/` 直接进入工作台总览。
- 验证 `/passphrase`、`/vehicle`、`/candidates`、`/progress`、`/result` 仍可访问。
- 验证页面文案不再出现“三天”“72 小时”“每次重新采集”等过时表述。
- 验证紧凑模式刷新后保持。
- 验证按钮文字、图标、表格内容在桌面和平板宽度下不溢出。
